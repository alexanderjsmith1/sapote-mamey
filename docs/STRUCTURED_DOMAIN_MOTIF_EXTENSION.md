# Structured-domain/motif sidecar: source and receipt boundary

This Markdown companion explains the [structured-domain/motif HTML candidate](STRUCTURED_DOMAIN_MOTIF_EXTENSION.html). Use this sidecar when you already have a pinned base database and saved structured Mamey exports; use the reference-BGC extractor for a separately curated exact-reference panel. It indexes exports, not original antiSMASH JSON or new scientific analysis. Export hashes bind file bytes; row hashes bind canonical JSON content, not its original whitespace or key order. Source/locus/gene/protein binding does not validate biochemical function, product, activity, novelty or scientific acceptance.

`mamey/structured_domain_motif_extension.py` checks export hash/schema/table counts and consumed-file checksums. Missing input or checksum conflict is held; a file not listed in package checksums can be hash-captured rather than a full package-checksum pass. Source archive/manifest/geometry/roster/protein holds stay typed. Empty exported tables are `EXPORTED_EMPTY_NOT_BIOLOGICAL_ABSENCE`. Unsupported motifs/predictions stay sidecar-only; do not promote them into compatible domain evidence just because they are indexed.

## Publication and resume

CLI requires inventory pin, source root, base pin, output, allowed root and receipt. Inventory paths and package names are validated through the shared source owner. Output DB containment is checked before opening; an existing DB requires `--resume`. Base bytes are checked before and after build. Resume binds base hash and normalized inventory content, rechecks completed partition files/verified archives, and can return `RESUME_COMPLETE_OUTPUT_UNCHANGED`. This does not independently certify the sidecar code/runtime or a historical scientific decision.

Limits: 128 inventory packages, 64 MiB per export or sidecar, and 100,000 observations per package. The 900-second timer is checked **between partitions**, not a hard timeout within one package. Commits occur per package; budget/parse/output failure can retain a partial DB with committed partitions. Final integrity/foreign-key checks are assertions, not a complete scientific validator. Preserve partial output and the original input inventory; use governed resume with unchanged pins rather than deleting evidence to bypass a hold.

The receipt root is checked **after DB build**, and the receipt is directly written afterward. There is no existing-receipt refusal or collision check against the output DB, base DB or source inventory. Choose a fresh receipt path disjoint from all inputs and the DB, inside the allowed output root; the root check alone does not preserve existing evidence. A bad receipt path/write failure can leave a built DB without a published receipt. JSON progress lines may appear before a final refusal; process exit 2 is `REFUSED_OR_CHECKPOINT_REQUIRED`, not empty-output assurance. DB and receipt are not one transaction. The returned DB hash/size is useful but the receipt lacks its own hash and full code/parameter pin. Record actual process status, DB, receipt, source inventory, code and parameter hashes separately; do not treat “all saved packages” as the whole project's scientifically accepted cohort.

## Reader and full-identity constraints

The inspection callback needs both already-open, caller-pinned native SQLite connections in read-only transactions. It rechecks file hashes, exact 50-section number, profile hash and requirement parity, limits 1–500, and bounded result size. It provides no generic CLI dispatch: parent shared-reader integration is separate. Raw rows additionally need an explicit package root and verified export/raw-row hashes.

A gene-first evidence index requires a complete locus and compatible domain observations with gene hash/hold checks. `BOUND` checks package-locus geometry and gene/protein linkage; it does not independently validate every domain/motif row's interval or biological meaning. `EXACT_BASE_FEATURE_PROVENANCE_MATCH` additionally requires the recorded feature type, coordinates, full qualifiers and explicit gene set to agree with the pinned base. Preserve strain / full node-or-contig / region / BGC alias. Pagination is over source rows, not guaranteed genes or a complete locus inventory. `READ_ONLY_CANDIDATE_INSPECTION` explicitly records scientific admission `NOT_PERFORMED`. Section parity does not validate a current50 v2 authored card or approve any scientific claim. Record sidecar builds, callback execution, dataset changes and rendering as separate actions with their own receipts.
