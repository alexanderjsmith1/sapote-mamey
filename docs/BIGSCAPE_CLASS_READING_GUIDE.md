# Reading BiG-SCAPE classes

Use the [generated class vocabulary](BIGSCAPE_CLASS_GLOSSARY.md) with these consumer limits. Bind database, run and cutoff identities before reusing a class label.

## Consumer and reviewed-subtype binding limits

This vocabulary is generated by `tools/bigscape_class_glossary.py` from `mamey/data/bigscape_class_vocabulary.json`. Codes are broad source-label routing terms, not verified class/function assignments. The “direct edge distance” reading applies only to a consumer that actually emits measured pairwise edges; the static strain/GCF hub view connects membership, not pairwise distance. Inspect the figure/table producer and its run scope before reading an edge as a measurement.

The current cohort-report subtype loader keys rows on the literal `family_id` alone, validates nonblank required metadata and refuses conflicting subtype records for that ID. It does not bind the row to database hash/run/cutoff or authenticate reviewer identity/evidence. Supply a subtype table dedicated to the selected exact run/cutoff and externally record its source/hash/authority; do not reuse family IDs across runs. A schema-valid “reviewed” row is supplied interpretation, not proof of owner acceptance (`tools/bigscape_cohort_report.py:158–175,375–392`). Complete strain/full contig/region/alias identities still require their separate binding; a vocabulary code or displayed family label cannot supply one.
