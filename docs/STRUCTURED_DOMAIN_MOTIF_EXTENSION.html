Structured domain and motif extension candidate

This module indexes existing Mamey structured exports. It does not parse original antiSMASH results JSON or run a new scan. Source values remain in pinned exports, resolved by package, table and row identifier. The sidecar retains raw row hashes and typed binding holds.

Call the module with an explicit inventory SHA-256, package source root, base database SHA-256, output path and permitted output root. Portable inventory manifest and structured_path fields are relative to the source root; absolute paths and traversal are refused. Optional archive root/map supplies relocated source archives. Resume verifies input/dependency pins and completed partition sources before continuing; a completed resume preserves database bytes.

Limits:128 packages,64MiB per structured export,100,000 observations per package,64MiB sidecar and a900-second partition-boundary time budget. Budget failures retain committed partitions. No original JSON parsing or automatic cleanup occurs.

The inspection callback requires both caller-pinned, read-only native SQLite transactions from the shared reader owner. It verifies connection file hashes and exact50 requirement parity. Source rows need an explicit package root and matching source hash. Parent-owned callback dispatch is a prerequisite for integrated CLI inspection; this lane adds no competing generic reader.

Only compatible domain/HMM observations can map to the existing domain evidence-index channel. Unsupported motif and prediction kinds remain sidecar-only. Every bound row requires source archive identity, complete locus, geometry, complete gene roster and normalized protein hashes. Binding is provenance, not biological validation. Gene-first index pages require a complete target locus.

Package assembly variants remain distinct. Missing source, unsupported schema, exported-empty, row unbound and observed states are not interchangeable. An exported-empty RiPP/RRE table, especially with main JSON mode off, is not biological absence. Exact base feature matches require shared archive, locus, coordinates, full qualifiers and explicit genes; other overlaps are not silently collapsed.
