## General-audience Cluster C: output provenance, counters and missingness

Interpret JSON modes and extraction counters using the following channel-specific rules:

- **RiQ counters have different units.** In the bounded walker, `riq_mapped_count` counts distinct record-ID/region keys, whereas `riq_unmapped_count` counts observed score values, including multiple observations within one unbound region. They must not be added as a common-denominator region census or divided to report a mapping success rate. `riq_mapping_status=MAPPED` means at least one mapped key was found; unassigned values, truncation or parse errors can coexist with it.
- **The displayed summary may be one file, not the archive.** The walker initializes its RiQ dictionaries/counters per JSON member and assigns the top-level counters, mapping status and `riq_genome_summary` on each qualifying member. Later qualifying members overwrite those fields, while `by_region` accumulates entries from the members. The summary's `regions_with_riq`, median and maximum therefore describe the last member that writes that summary, not necessarily every mapped region in a multi-JSON archive. A member with only unmapped values can replace the counters/status while leaving an earlier summary. Retain the JSON-member provenance and rebuild an explicitly defined archive-level census before making such a claim; absence of a field is not a zero.
- **Observed maximum is not identity rescue.** The bounded walker accepts in-range numeric values under `scores_by_region` with a recognized region path. It binds scores only after a genuine top-level `records[]` object closes with exactly one nonblank string ID. Missing/duplicate IDs, incomplete records and values outside an admitted record/region remain in `loose_hits` with typed identity status. The maximum aggregates observed values within the admitted record/region key; it does not resolve an ambiguous biological identity or prove all scores were observed.
- **The cap is a selected-string-leaf budget.** Despite its constant name, the active bounded limit of 200,000 counts selected string leaves, not records, BGCs, genes or all scores. The bounded main walker admits JSON members up to 250,000,000 uncompressed bytes when ijson is available. RiQ values are processed before the leaf-budget check, but later unobserved values can still be lost after the loop stops. ## Volume I section 7.2: gate states, reason text and hub-degree scope

Interpret confidence gates and graph counters as software conditions, not empirically calibrated compatibility or precision.

- **The cascade is stateful and is not universally HIGH-to-MODERATE.** Geometry can change HIGH to MODERATE and then MODERATE to LOW in the same call. Subsequent product/R1/R2/R3 gates act only on incoming HIGH; their `OK` return for other confidence states means that gate did not demote that state, rather than a new positive evidence check. Preserve the incoming and outgoing states when interpreting each reason.
- **Class compatibility is a text-policy result.** P2 tokenizes product text, adds class-family tokens and applies its local exclusion/umbrella sets; a shared class or configured compatible pair can retain HIGH. This consumer does not establish that a biological hybrid or experimentally compatible split exists. R1/R3 use their own nonempty token-set predicates and local token lists, rather than the current standing-rule registry. A neutral/nonblocking standing-rule decision in the registry does not automatically make the same named token neutral in RG-GMCI's local class gate. Keep these policy scopes separate.
- **Reason strings are a transition trail, not a final verdict whitelist.** Geometry precedes product gating, a restricted co-cluster exception can restore the post-geometry state, and then R1/R2/R3 run. A later subject-paralog branch can lower HIGH or MODERATE to LOW; a later restoration path can raise an eligible MODERATE pair while rerunning R1/R2/R3. Consequently final HIGH may coexist with earlier demotion text and a restoration suffix in `acceptance_gate`. Read the final confidence alongside the full transition trail; do not reject or accept a row solely because its reason string contains 'DEMOTED' or 'OK'. The biological conditions of later restoration are subject to separate evidence validation.
- **R2 counts raw comparison support, not separate strength on each arm.** Its argument is the counter of shared-reference comparisons whose joint helper label was HIGH at accumulation time. The reference wording 'neither side has a strong reference' can misleadingly imply two independently tested arm-level strength fields. Retain the exact joint counter and its admitted reference denominator from the pair-score clarification.
- **Hub degree is a snapshot of post-gate HIGH pair rows.** The guard counts one incidence per HIGH row at each endpoint before any hub demotion, then uses the maximum endpoint count for every row. It does not count component size, the number of raw references, all MODERATE links or the number of experimentally confirmed fragments. It demotes qualifying HIGH rows in one pass; it does not recompute degrees iteratively after each demotion. The recorded value is this pre-hub-demotion snapshot, not final surviving HIGH degree. Native pair aggregation provides one row per alias pair; imported duplicate rows are not deduplicated by this helper.
- **Ordering and summary ceiling have narrow meanings.** Pairs are numerically sorted before the hub guard, and the guard mutates confidence without re-sorting by that confidence. Final HIGH need not occupy every top row. The summary ceiling HIGH/MODERATE/LOW/NONE is the highest remaining label among evaluated pairs; it is not a cohort-wide scientific claim ceiling or proof that no relationship exists when NONE. Counter denominators and computational admission remain essential.

When explaining results, retain numeric score, incoming/final confidence, complete gate trail, local policy/registry scope, pre-demotion degree and evaluated-pair universe separately. Preserve full row identity. 'Precision enforcement' means implemented routing gates here; validate empirical precision, specificity and physical linkage independently.

## Volume II B.4: assembly input scope, independent tier fields and warning limits

Use `mamey/assembly.py` for the weighted-count and BGC-boundary tier definitions. These fields describe the supplied parsed inventory. Their names and generated warnings must not be interpreted as whole-genome completeness or independently measured contamination.

- **Two different tier fields answer different software questions.** `bgc_counts.assembly_tier` is calculated from the percentage of parsed BGC records with exact `Interior` boundary status. The manifest rounds that percentage to one decimal before selecting the named band. Unknown/unrecognized boundary labels remain in the raw-record denominator but are absent from the three named boundary counts used in corrected_count. This weighted count is not a reconstructed integer count or an estimate proven to recover missing BGCs. `assembly.quality.fragmentation_tier` is separate: it uses recorded contig count and N50. A `GOOD` BGC-boundary tier can coexist with fragmented contiguity. For table or caption decisions, preserve both fields and their bases.
- **Contiguity bands require both conditions.** `fragmentation_tier` chooses the first band for which contig count is at most the band's limit and N50 is at least its minimum: CLOSED(2;1,000,000bp), CONTIGUOUS(20;500,000bp), DRAFT(100;100,000bp), FRAGMENTED(1,000;10,000bp). Missing/nonpositive contig count returns `UNKNOWN`. With a positive contig count, missing N50 is currently replaced by zero for band comparisons and falls through to `HIGHLY_FRAGMENTED`; that result does not establish measured severe fragmentation. The band labels are configured descriptors, not closure validation or taxonomic/scientific acceptance. The generated caveat sentence is template output, not an actual assessment of a phylogenetic tree.
- **Metric denominators are distinct.** `metrics_from_sequences` counts supplied dictionary entries as contigs and uses full string lengths for genome_bp, largest_contig and N50. Overall GC uses only A/C/G/T characters in its denominator; ambiguity characters contribute to length but not GC. The sanity dispersion is a length-weighted population standard deviation of per-contig GC percentages over eligible nonempty records, and needs at least two records with a defined GC percentage. A missing dispersion value is not zero variation or evidence that contamination was ruled out. Preserve the metric name, unit and eligible-input count rather than calling every number a whole-genome measurement.
- **The ZIP metric path prefers FASTA and excludes region GBKs on fallback.** `assembly_metrics_from_zip` returns FASTA-derived metrics when any FASTA sequence dictionary is available. Otherwise it collects non-region GenBank records, skips members whose basename contains 'region', and retains the longest sequence for each resolved contig ID. With region-only input it returns zero size/count and missing N50/GC; this is unavailable assembly scope, not proof of a zero-size genome. The function does not attach a dedicated region-only unavailability state. Validate FASTA selection and upstream record binding before treating these metrics as whole-assembly measurements.
- **The sanity probe currently uses a different fallback universe.** In `mamey/cli.py:2057–2066`, the probe also prefers FASTA; its GenBank fallback does not apply the metric producer's region-filename exclusion and resolves/deduplicates names by a different local expression. Therefore sanity stats and manifest assembly metrics cannot be assumed to have identical record membership when FASTA is absent. Compare their explicit source scope before using a size warning to decide that an entire submission is incomplete.
- **Warnings are heuristic software states.** The helper's configured GC-dispersion threshold is 5 percentage points; an optional expected-GC prior uses an 8-point difference, and expected-size range tests require a supplied range. Its default minimum-size floor is 3,000,000 bp, with a further partial-submission flag when the below-floor nonzero input has at most 5 records. The CLI call supplies no taxon priors or explicit floor override. A helper caller can disable the floor with `min_genome_bp=None`, a corresponding CLI option is not established by this helper signature. These default warning states are not taxon-specific validation. Empty input does not trigger the nonzero-size condition, so an empty flag list is not a completeness certificate.
- **Failure and warning must remain separate from absence.** The sanity helper returns flags and statistics without rejecting extraction. The CLI appends warnings to the issue channel; an exception produces `ASSEMBLY_SANITY_PROBE_FAILED` and an ERROR phase receipt with completeness/contamination unverified. A run/package completion state or absence of a warning does not independently establish whole-genome input, contamination freedom or scientific readiness. Review the current run's source records and receipts before drawing those conclusions.
