# Sapote–Mamey Run Observations — TEMPLATE

## Scope, privacy and evidence before filling

This is a manual observation template. It does not execute an analysis, generate a figure, establish a
source seal or certify its claims. Use the [canonical glossary](../GLOSSARY.md),
[profile matrix](../MODEB_PROFILE_MATRIX.md) and [reading-results guide](../READING_YOUR_RESULTS.md).
Record the actual producing bundle/engine, task scope and selected profile; an old template or title stamp
is not the current source version. Preserve exact metrics, units, denominators and typed missing states.
If no admitted numerical evidence exists, state that hold rather than manufacturing a quantitative result
or figure to satisfy the introductory pairing suggestion. Label measured-negative separately from not tested,
not supplied, unread or unbound evidence.

The header's PUBLIC/PRIVATE field records actual source/release metadata; it is not disclosure or publication
authority. Record the task's allowed audience separately and retain trusted affiliation metadata. A historical
PRIVATE worked-example mention is not permission or proof that its artifact is supplied or currently valid.
Reference existing sources and artifacts in place by path/SHA-256; keep one candidate and actual source/review
receipts instead of copying package/evidence corpora. Authored interpretation, mechanical checks, independent
review, rendered visual QA and owner adoption are separate states. Claim visual review only after actual
rendered pages were inspected; claim no experiment, activity attribution or novelty from template completion.



*A "Run Observations" deliverable records the reviewer's qualitative and quantitative observations on one analytical
thread (a BGC, a reconstruction, a cross-strain comparison) in a fixed, reusable shape. Pair it with a
companion figure and/or table so it is genuinely both qualitative and quantitative. Every claim is tagged
**observed** (in a named field/file) / **computed** (by a stated rule) / **inferred** / **assumed**.*

**Header:** scope (individual BGC / reconstruction / cohort thread) · producing bundle and engine versions · source package/archive and provenance receipt · release (PUBLIC/PRIVATE) · affiliation.

For an individual BGC observation, record all four fields together before the observation: **strain / full node-or-contig / antiSMASH region / source-scoped BGC alias**. Copy them from the bound source; a bare alias or shortened contig is insufficient. If any field cannot be rebound, mark the observation **IDENTITY_BINDING_HOLD** and do not attribute evidence to that locus.

For a reconstruction involving multiple source regions, list each complete four-part identity separately. For a non-locus cohort or workflow observation, mark locus identity **NOT_APPLICABLE — <reason>** and bind the actual roster/scope instead. NOT_APPLICABLE is not a replacement for missing identity in an individual-locus observation.

## Observation (qualitative)
What was found, in plain reflective language — the finding stated before the evidence.

## Quantitative evidence
The numbers, tagged. Tables/figures referenced by filename. (e.g. ortholog %id/%cov; corrected count; board scores.)

## Reflection (what it means, what it refines)
Class placement (claim-safe: "biosynthetic capacity consistent with"), why the engine read it the way it did,
what earlier calls this refines or supersedes.

## Honest flags
Refuted hypotheses, twilight-zone artifacts, claim-safety limits, what is NOT established. The negative results
on the record.

## Confidence
Per-claim confidence (high / open / unestablished), separating class-level from product-level from activity-level.

*Reusable for any strain/BGC. A worked example (a polyoxin-family peptidyl-nucleoside reconstruction) ships separately as a PRIVATE deliverable.*
