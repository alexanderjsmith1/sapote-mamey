What Sapote–Mamey is

Sapote–Mamey is a genome-mining pipeline for actinomycete natural product discovery. It takes antiSMASH output — ZIP files from the standard BGC detection tool — and produces prioritised, scientifically grounded, wet-lab-actionable interpretations of every biosynthetic gene cluster in a genome.

The pipeline has two layers. Mamey is the deterministic Python engine: it parses antiSMASH ZIPs, runs ten source-derived scans, scores every BGC on two axes (antibacterial and antifungal), and emits a sealed package containing the triage board, workbook, strain brief PDF, and figures. Sapote is the LLM judgment layer: a structured protocol that applies claim-safe interpretation on top of Mamey’s facts — the Mode B deep dives, ecological hypotheses, BLASTP batch campaigns, and experimental decision trees that turn a BGC score into a research plan.

The contract between the two layers is the pipeline’s most important design choice. Mamey says what the data says. Sapote says what it might mean. Neither claims more than the evidence supports. Every compound class assignment is capacity-level — “biosynthetic capacity consistent with X” — never a production or identity claim. A KCB hit is similarity, not identity. Bioactivity is extract-level until fractionation.

How a run works

antiSMASH output
Your genome → antiSMASH → a ZIP file with region GenBank files and run JSON. Mamey reads this. It does not run antiSMASH itself.
mamey run
Parses the ZIP, runs 10 scans (KCB sweep, RG-GMCI, CCTT triggers, resistance genes, bldA/TTA, UMED, FLBR, TFBS, compound class, chitinase), scores BGCs, emits triage board + workbook + strain brief PDF + locus maps + sealed package.
→ MAMEY_COMPLETE
Post-MAMEY_COMPLETE handback
Figures, strain brief PDF, locus maps, workbook, and checksums are presented automatically before any prompt-backed deliverables. The Deliverable Menu lists everything available.
Sapote judgment — Mode B cards
Full §1–§20 deep dive per high-priority BGC. §28 (evidence provenance ledger) and §30 (experimental decision tree) required for every completed card. §21–§29 optional extensions available for RiPPs, novel compounds, and isolation candidates.
Mamey-first gate: Mode B refused without sealed package
BLASTP → fermentation → isolation
BGC-specific BLASTP batches (3 proteins per batch, nr database), fermentation cards with OSMAC protocols, LC-MS mass targets from the §21 precursor mass ladder. The §30 decision tree specifies which experiments come next and what each answer changes.

New features

v9.7.119 → v9.7.147
New

Edge/FC BGC equality in fragmented assemblies

Edge and full-contig BGCs no longer get buried below interior BGCs. In POOR or VERY_POOR assemblies (<45% interior), the interior/edge distinction is mostly an assembly artefact — it reflects where a contig was cut, not whether the cluster is biologically complete. All detected BGCs now appear in the triage board sorted by score, not by boundary status.

Edge BGCs receive full Mode B depth. The boundary caveat belongs in §3 and §19 only. The Wet Lab Matrix −2 edge penalty is suppressed for POOR/VERY_POOR assemblies. The AS-XXX polyene megacluster — four full-contig fragments forming one pathway — would have been partially buried under the old rules.

v9.7.147
New

§28 Evidence provenance ledger + §30 Experimental decision tree

§28 is a per-claim table in every completed Mode B card. Each factual claim traces to: source file, evidence tier (observed / computed / inferred / assumed), engine version, confidence, and the trigger for updating it. Makes cards surgically updatable when new BLASTP results arrive — find the rows that change, update them, done.

§30 is five open questions, each with the resolution experiment, what the result would change in the card, and the downstream programme consequence. The AS-XXX BGC044 ranthipeptide §30 answered: where is the leader protease, is ctg73_20 a second substrate, does QueE contract the ring, Cl or Br, and is the pathway expressed. Both sections required for every completed card.

v9.7.147
Architecture

ChatGPT Execution Slice — replaces the slim kernel

The SAPOTE_SLIM_JUDGMENT_KERNEL.md was a 379-line compressed version of the pipeline rules for LLMs with tight context windows. It created “path of least resistance” behaviour: abbreviated rules are easier to satisfy than the full scientific floor.

The new CHATGPT_EXECUTION_SLICE_v97147.md has no abbreviated rules. It requires full Mode B depth for every BGC, rank-sorted triage, post-MAMEY_COMPLETE handback, and §28/§30 for every completed card. The slim kernel is retained for backwards compatibility but removed from every default load path.

v9.7.147
Architecture

Mamey-first gate

If you ask for Mode B without a sealed Mamey package, the analysis chat refuses and redirects. This fixes a real failure: a Mode B card written from raw antiSMASH GBK files missed the correct Interior boundary (the raw contig_edge=True flag is misleading when the BGC region has 6 kb of flanking buffer on each side), the SMCOG1119 halogenase on ctg73_25, the T43-HAL CCTT trigger, WL score of 7, and the KCB hit to S. flava. The same card from the Mamey package got all of these right. The gate enforces the right sequence.

v9.7.146
New

Post-MAMEY_COMPLETE handback + Deliverable Menu

After every run the analysis chat presents code-backed outputs before anything else: strain brief PDF, all figures with data CSVs, locus maps, workbook, checksums, issue log. Previously these existed in the package directory but were never surfaced unless explicitly requested — the machinery was there, the delivery wasn’t.

The Deliverable Menu is a plain-language list of everything available: triage board, lead sheet, layperson guide, locus maps, BLASTP batches, Mode B deep dives, full strain plate, fermentation card, wet lab matrix, ecological synthesis. Each item has a trigger phrase. You can combine them.

v9.7.146
Fix

Checksum integrity — root cause fixed after three audit cycles

Three consecutive ChatGPT audit cycles found checksums_sha256.txt always stale. The cause: packaging.py hashed every file, then wrote the mutable receipt files (run_phase_receipts.jsonl, package_status.json) after the hashes were already recorded. Every sha256sum -c run failed.

v9.7.145c added detection (verify_checksums wired into validate). v9.7.146 addressed the cause: write_manifest() now excludes mutable files from the hash set before computing checksums. A corrupted non-mutable file now correctly causes status: FAIL.

v9.7.145c / v9.7.146
New

Mode B interpretive floor

Per-section minimum depth requirements, defined in docs/MODEB_INTERPRETIVE_FLOOR_v97146.md. The problem: cards were structurally complete (20 sections present) but interpretively thin — gene tables detailed, findings not flowing forward. §5 named domains without connecting them to structural consequences. §9 listed alternatives without weighing them. §19 restated §11 without arguing the verdict.

The floor specifies: §5 must explain what the domain arrangement produces molecularly. §9 must give evidence for and against each alternative and name the most parsimonious hypothesis. §12 must name the host-specific ecological mechanism. §19 must argue through evidence summary → alternative rejection → claim ceiling.

v9.7.146
New

Locus map SVG renderer

New mamey/figures/locus_map.py generates gene-arrow locus maps as SVG directly from antiSMASH region GBK files. Pure Python, no matplotlib dependency. Produces directional gene arrows colour-coded by biosynthetic role, domain bars (enoylreductase, docking, P450), truncation markers at contig ends, scale bar, legend. Emitted alongside every Mode B card when a GBK is available.

v9.7.145
New

BLASTP batch emitter

New mamey/blastp_batch_emitter.py generates ready-to-submit FASTA batches with companion READMEs for NCBI BLASTP. Three proteins per batch (NCBI’s practical processing limit), sequential integer numbering always, SIGXFSZ recovery for oversized-sequence rejection. Used for the AS-XXX megacluster campaign: 30 proteins across 9 batches, covering four contigs of a novel polyene PKS pathway.

v9.7.145
New

Node notation validator

New mamey/validators/node_notation.py enforces the citation rule that every BGC must be referenced as BGC028 (NODE_32_length_60747_cov_53 · region001) at first mention in each section. A bare BGC number is unciteable — the node is the assembly locator. Fixed four edge cases: bare NODE references without region, BGC IDs in headings not checked, per-section seen-set not resetting across headings, and an overzealous inline-citation regex.

v9.7.145
Governance

Engine lineage governance

New docs/ENGINE_LINEAGE.md records every engine version bump with reason, affected bundle, and whether scoring semantics changed. sync_version.py --check exits non-zero if the current engine has no entry. Motivated by the undocumented 1.9.99→1.9.100 bump at v9.7.142, which was invisible until audited months later.

v9.7.145
Architecture

Trigger routing table

New docs/TRIGGER_ROUTING.md is the single authoritative table for what happens when any named trigger fires. Previously routing was distributed across five documents with no conflict resolution for the OFFLINE_EVIDENCE_ALLOWED vs WISE_PKS_QUEUE_DETECTED conflict. All trigger constants are now in one place with explicit guards.
