## Completion and evidence

A completed extraction is not completed interpretation or a finished authoring suite. Outputs depend on profile, options and phase success; brief/locus maps and optional enrichments are not guaranteed in every package. Inspect the manifest, issue log, phase receipts and selected workflow's expected outputs. The legacy suite checker reads reported manifest text and does not prove file existence, hashes, exact identity or content; consult [checker scope](DELIVERABLE_MANIFEST_TEMPLATE.md).

A persisted register's COMPLETE value and successful export are not selected-profile verification. Use the same contract, verify actual cards and bind receipts to source/package/artifact hashes. Where a code path lacks those bindings, preserve the hold rather than converting a status into scientific acceptance.

Post-seal commands have different write contracts. Use [post-seal reader guidance](POSTSEAL_READERS.md) and working copies for authoring/rendering where necessary. Reference source evidence by path and SHA-256; copy only files that need isolated modification. Preserve full `strain / full node-or-contig / region / BGC alias` for individual loci.

Predictions, similarity anchors, missing anchors, heuristic ranks and class labels do not prove a compound, activity, causality or novelty. Use supplied typed assay metadata for assay wording; absence stays unknown. Actual privacy/profile and owner review determine audience and release eligibility. [Custom privacy tiers](CUSTOM_PRIVACY_TIERS.md) and the cut protocol document current release boundaries; inventory presence grants no release authority.
