# Finding a deliverable and checking what exists

Use [the product map](PRODUCT_MAP.md) to choose a workflow, [the generated deliverable menu](DELIVERABLE_MENU.md) to find a registered outcome, and the owning command guide to identify concrete output paths and status. The menu's output labels are catalog descriptions; they are not a promise that those files exist in a selected package. Use [per-mode outputs](PER_MODE_ARTIFACT_SET.md), actual files, hashes, phase receipts and [result reading](READING_YOUR_RESULTS.md) for a particular run.

## Registry-backed menu and availability

The menu and [version-pinned compatibility pointer](DELIVERABLE_MENU_v97146.md) are generated from `mamey/data/deliverables_registry.json` by `tools/generate_deliverables_menu.py`. Preserve generated files; correct the registry in a governed candidate and regenerate both together. Default/`--check` compares expected rendered text and returns 1 for stale/missing files. `--apply` overwrites each generated file using a temporary sibling and replacement; it is a release/candidate maintenance action, not part of reading a package. The files are written sequentially, not as one transaction.

The CLI supports `deliverables list`, `deliverables explain ITEM` and `deliverables availability [ITEM]` with `--json`. Availability accepts `--package`, `--runs-dir`, `--input-zip` and `--locus`. This is a shallow local preflight:

- A `sealed_package` requirement checks only `<package>/manifest.json` presence. ZIP or run-root inputs that readers accept are not normalized here.
- Multiple packages count the exact `*/package/manifest.json` pattern directly below `--runs-dir`; unrelated layouts are not recursively discovered.
- `--input-zip` is checked as an existing file, not validated as an antiSMASH archive.
- Complete locus input is checked for three literal ` / ` separators and a BGC token; the four identities are not resolved against evidence.
- Selected tools/modules are checked for discoverability; governed/scientific inputs remain declared for review.

`READY` means those catalog checks found no missing or declared requirements for that item. Other states name input/dependency, judgment, external-contact authorization, human review or declared-input holds. `availability` returns 0 even when rows are not ready; inspect each state and missing/notes fields. It creates no deliverable, validates no source bytes and grants no permission for external work. Source: `mamey/deliverables_registry.py:230–305,327–399`.

Some registry summaries need source-owner corrections. In particular G1's statement that additive receipt ingestion does not mutate the sealed package is broader than current CLI behavior: selected authoring commands write package-side artifacts and refresh `post_seal_checksums.txt` (`mamey/cli.py:8550–8569`). Use the owning command's concrete write contract and retain accepted core evidence; the menu alone is not an immutability guarantee. Correct the owning registry and regenerate the menu together when this source correction is adopted.

## Generated file atlas

[FILE_ATLAS.md](FILE_ATLAS.md) and `FILE_ATLAS.csv` are source-navigation aids generated by `tools/file_atlas.py`. They scan Python beneath `mamey/` and `tools/`, omit `__init__.py` and paths containing `_vendor`, `data` or `__pycache__`, and do not inventory the entire bundle. Parse failures are represented as empty source/counts, not explicit errors. Imports are matched by module stem; duplicate stems and dynamic imports can distort relationships. CLI association uses verb/stem text matching, not verified dispatch. Test references are word matches in `tests/test_*.py`, not test execution or complete coverage; shell/registry references are textual too.

An orphan label is a triage candidate, not proof of dead code or permission to delete. File counts, lines and test-name counts describe one generated snapshot and are not runtime, functional or release certification. Preserve it as generated evidence and consult owning Python source for an actionable claim. Regeneration writes supplied CSV/Markdown paths directly and sequentially, overwriting existing files; missing parent directories or a later write error can leave only one updated output. Use new output paths and retain partial outputs after a failed regeneration. Source: `tools/file_atlas.py:39–77,80–145,152–204`.

## Reader bundles and request names

[HTML template readers](HTML_TEMPLATE_READERS.md) names the separate menu, related-view, portfolio, explorer, next-evidence and reaction-board tools, including their input and recovery contracts.

For portable interactive pages, request the **`render-widgets` builder** and specify the reviewed source and separate output directory. [Widget deliverables](WIDGET_DELIVERABLES.md) lists exact files, fingerprint scope and interruption/overwrite behavior. A gene-table slide deck is a separate artifact and should be requested with its owning builder and source contract; the widget builder name does not identify that deck's builder.

Before requesting any artifact, bind input identity and hashes, desired format, selected profile, destination and acceptance owner. Preserve missing/failed/skipped states; software completion is separate from scientific and publication acceptance. This guide is a source-only documentation review, with no builder, validator or external workflow executed.
