# release_denylist.example.txt — reading template for private-term policy.
# This example ships publicly; never put actual private terms in this file.
# The active tools/release_denylist.txt is stripped from public tiers.
#
# HOW TO USE
# Create a separate tools/release_denylist.txt containing only your selected
# terms, one per line, with a final newline. Do not copy this commented template
# verbatim: the current reader skips only empty lines. A line beginning # and
# leading/trailing spaces are treated as part of a term, not as comments.
# Review the chosen terms before invoking any separately authorized tier cut.
#
# CURRENT NONMERGED CUT BEHAVIOR (tools/make_public_tier.sh:361-373)
# Content removal is case-sensitive sed replacement for selected text extensions
# (.md .csv .py .cff .txt .json .sh .yaml .yml .html), excluding wheels descendants.
# Name removal uses case-insensitive find -iname glob patterns, also excluding
# wheels descendants. Glob metacharacters in a term can broaden name matching;
# content and filename matching are not the same literal-string operation.
# The staged audit uses case-sensitive fixed-string grep with binary-file
# suppression (`make_public_tier.sh` step 3 leak audit). A matching text term refuses the cut. This is not
# proof that every binary payload or alternative spelling has been checked.
# Do not list terms whose removal would corrupt evidence or required code.
#
# STRAIN IDS
# The identifier redactor is an explicit utility, not an automatic cut transform
# (`make_public_tier.sh` step 2 block). Other admission/audit gates have their own scope; do not infer
# that cutting a tier rewrites every strain identifier or certifies privacy.
# Review and classify private inputs before a separately authorized cut.
