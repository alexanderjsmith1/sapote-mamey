# Moved: BiG-SCAPE reader recovery

This note described older versions of the BiG-SCAPE readers. These readers now refuse a missing database file and open an existing one read-only: `tools/bigscape_family_verdicts.py`, `tools/bigscape_family_figures.py`, `tools/bigscape_clinker_html.py`, `tools/bigscape_family_domains.py`, `tools/bigscape_mibig_anchors.py`, `tools/bigscape_ingest_to_mamey.py` (`--db`) and `figures gcf-network`. Run selection differs by reader. `bigscape_family_verdicts.py`, `bigscape_family_figures.py` and `bigscape_clinker_html.py` take `--run-id`; when `family.run_id` is present, they require a choice if more than one eligible run exists. If `run.end_time` is present, runs with no recorded end time are rejected when named and excluded from automatic selection. If that column is absent, completion is not checked: verify completion from independent run evidence. Legacy databases without `family.run_id` cannot establish run-scoped membership through this selector. `bigscape_family_domains.py`, `bigscape_mibig_anchors.py` and `bigscape_ingest_to_mamey.py --db` always require `--run-id`. `figures gcf-network` requires `--run`. The verdict table and its placement file record the run in a `run_id` column. The old note is kept as a record in [old BiG-SCAPE reader notes](../docs/history/BIGSCAPE_READER_RECOVERY_OLD_READERS.md).

For current problems, use [BiG-SCAPE troubleshooting](../docs/troubleshooting/BIGSCAPE_TROUBLESHOOTING.md).
