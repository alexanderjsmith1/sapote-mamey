# Sapote-Mamey Multi-Cohort Comparison Toolkit

Request this by name: **Sapote-Mamey Multi-Cohort Comparison Toolkit**, with the specific tool and bound input/output paths. Its front door is `deliverable_tools/cohort_tools.py`.

The launcher uses Python standard-library facilities to list and dispatch tools. Individual tools can require the Mamey modules, governed exclusions data, Python packages, external binaries, or a particular workspace layout. `list` and `doctor` do not check each tool's own needs.

## Discover tools before dispatch

From the bundle root, using the selected Python environment:

```bash
python deliverable_tools/cohort_tools.py list
python deliverable_tools/cohort_tools.py doctor
```

`list` reads local script descriptions. `doctor` checks executable locations and path existence; it does not test package imports, binary compatibility, reference databases or a scientific workflow. The doctor uses `SAPOTE_ROOT`, defaulting to `~/sapote_workspace`, for its project-path probes. Tools such as `enrich_swissprot.py` and `build_strain_dossier.py` instead use `SAPOTE_WORKSPACE_ROOT`, defaulting to the current working directory. These variables have different owners and purposes.

The dispatcher runs Python tools with the same interpreter as the launcher and shell tools with Bash. It forwards arguments without supplying a dry-run or protective output copy. A dispatched `-h` is passed to the selected script: imports or shell actions can occur before any help handling. Inspect the selected tool first, especially shell batches.

[TOOLS_INDEX.md](TOOLS_INDEX.md) is generated by `cohort_tools.py index`, which overwrites it; do not edit it by hand. It also lists helper modules whose names start with `_`; those are not workflows. Read a tool's source before running one with no description.

## Inputs and writes depend on the selected tool

| Tool or surface | Contract to check |
|---|---|
| `enrich_swissprot` | Reads existing local Swiss-Prot CSV results and `sapote_deliverables/roster_v2/<strain>_roster_v2.json`; writes the roster back in place. It does not run BLASTp. Use an isolated candidate containing only the rosters to be changed, retaining their expected relative paths; reference existing inputs in place where the tool permits. |
| `backfill_coords_from_antismash` | Chooses the first archive with a non-input JSON member, then reads the first such member. Joins coordinates and ClusterBlast values by locus tag alone; repeated tags can replace earlier record entries. Reconcile exact archive, record, full locus and protein before updating an isolated roster candidate. |
| `build_strain_dossier` | Reads roster JSON, novelty board, comparison CSV and existing roster text. Writes Markdown and attempts DOCX in both `strain_data/<strain>/` and `sapote_deliverables/dossiers/`. DOCX requires the conversion helper, Pandoc and python-docx; an optional conversion failure can still return `ok` after writing Markdown. Inspect both destinations and actual formats. |
| `_batch_enrich.sh` | The shipped script quotes the workspace expression literally in `cd` and calls historical `sapote_deliverables/tools/` paths. Treat it as a blocked legacy batch recipe pending repair; do not use it as the portable front door. |

The Swiss-Prot join matches only `(bgc_id, gene)` to roster `(bgc_id, locus_tag)`. It does not check the full contig and region or protein hashes. A blank `hit_rank` counts as rank 1, and a repeated key overwrites the earlier row in glob order, so the kept hit is not reproducible. Unmatched genes keep their old values. Back up the roster and remove duplicate keys before enriching.

Several tools load exclusions through `mamey.exclusions` before parsing arguments. For example, `build_strain_dossier.py` uses non-strict `raw_analysis_excluded()`: a failed binding can warn and fall back to empty exclusions; its import wrapper raises only when an exception escapes. This is not the strict governed accessor or a guaranteed missing-pack refusal. Inspect that owner and provision the selected data source; do not invent an empty exclusion set to bypass the failure. See [companion files](../docs/COMPANION_FILES.md), [external assets](../docs/EXTERNAL_ASSETS_GUIDE.md) and the [companion protocol](../docs/LLM_COMPANION_TOOL_PROTOCOL.md).

For each requested tool, bind its inputs, dependency/data requirements, output directory, overwrite behavior and actual write targets from its source. Use a fresh output destination or copied workspace as appropriate. Dispatch only the requested operation; a tool being listed does not authorize every tool in the suite. Capture its exit status and inspect the expected artifacts. No-input, skipped, missing-channel and partial results need explicit reporting.

## Interpretation and recovery

These tools reorganize existing evidence. A capacity class, similarity, panel singleton or cohort-private label does not establish compound identity, production, activity or biological novelty. Bind panel denominators and source versions. Preserve `strain / full node-or-contig / region / BGC alias` for every individual locus.

If dependency loading fails, resolve the named dependency or governed-data gap before retrying. If a tool writes rosters or a workbook, inspect actual mutations and recover from the preserved copy rather than assuming a nonzero exit prevented writes. Figure, Word and PDF outputs need artifact inspection and rendered-page review before visual quality is claimed.
