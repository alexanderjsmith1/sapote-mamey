# Sapote-Mamey Multi-Cohort Comparison Toolkit

Request this by name: **Sapote-Mamey Multi-Cohort Comparison Toolkit**, with the specific tool and bound input/output paths. Its front door is `deliverable_tools/cohort_tools.py`. It ships alongside the engine in this v9.7.447 bundle; the historical v9.7.349 introduction is not the current bundle version.

The launcher uses Python standard-library facilities to list and dispatch tools. Individual tools can require the Mamey modules, governed exclusions data, Python packages, external binaries, or a particular workspace layout. A successful catalog or doctor probe does not establish those requirements are satisfied.

## Discover tools before dispatch

From the bundle root, using the selected Python environment:

```bash
python deliverable_tools/cohort_tools.py list
python deliverable_tools/cohort_tools.py doctor
```

`list` reads local script descriptions. `doctor` checks executable locations and path existence; it does not test package imports, binary compatibility, reference databases or a scientific workflow. The doctor uses `SAPOTE_ROOT`, defaulting to `~/sapote_workspace`, for its project-path probes. Tools such as `enrich_swissprot.py` and `build_strain_dossier.py` instead use `SAPOTE_WORKSPACE_ROOT`, defaulting to the current working directory. These variables have different owners and purposes.

The dispatcher runs Python tools with the same interpreter as the launcher and shell tools with Bash. It forwards arguments without supplying a dry-run or protective output copy. A dispatched `-h` is passed to the selected script: imports or shell actions can occur before any help handling. Inspect the selected tool first, especially shell batches.

[TOOLS_INDEX.md](TOOLS_INDEX.md) is generated by `cohort_tools.py index`. Do not edit it independently. Its recorded count and descriptions are a snapshot, not proof of the current catalog. `index` overwrites that file inside the bundle; regenerate only in an authorized working copy. The current generator also catalogs underscore-prefixed helper modules because it excludes only the launcher; private helpers such as `_console` are not user workflows. A missing docstring is a documentation gap, not permission to run an unknown script.

## Inputs and writes depend on the selected tool

| Tool or surface | Contract to check |
|---|---|
| `enrich_swissprot` | Reads existing local Swiss-Prot CSV results and `sapote_deliverables/roster_v2/<strain>_roster_v2.json`; writes the roster back in place. It does not run BLASTp. Use a copied workspace when originals must be preserved. |
| `backfill_coords_from_antismash` | Searches workspace strain archives and fills existing roster coordinates, writing roster JSON back. Inspect archive selection and preserve original rosters before dispatch. |
| `build_strain_dossier` | Reads roster JSON, cohort novelty board, comprehensive comparison CSV and existing roster text. Its source determines dossier outputs and any conversion dependencies. |
| `_batch_enrich.sh` | The shipped script quotes the workspace expression literally in `cd` and calls historical `sapote_deliverables/tools/` paths. Treat it as a blocked legacy batch recipe pending repair; do not use it as the portable front door. |

Several tools load exclusions through `mamey.exclusions` before parsing arguments and refuse if governed exclusions are unavailable. Inspect that owner and provision the selected data source; do not invent an empty exclusion set to bypass the failure. See [companion files](../docs/COMPANION_FILES.md), [external assets](../docs/EXTERNAL_ASSETS_GUIDE.md) and the [companion protocol](../docs/LLM_COMPANION_TOOL_PROTOCOL.md).

For each requested tool, bind its inputs, dependency/data requirements, output directory, overwrite behavior and actual write targets from its source. Use a fresh output destination or copied workspace as appropriate. Dispatch only the requested operation; a tool being listed does not authorize every tool in the suite. Capture its exit status and inspect the expected artifacts. No-input, skipped, missing-channel and partial results need explicit reporting.

## Interpretation and recovery

These tools reorganize existing evidence. A capacity class, similarity, panel singleton or AS-private label does not establish compound identity, production, activity or biological novelty. Bind panel denominators and source versions. Preserve `strain / full node-or-contig / region / BGC alias` for every individual locus.

If dependency loading fails, resolve the named dependency or governed-data gap before retrying. If a tool writes rosters or a workbook, inspect actual mutations and recover from the preserved copy rather than assuming a nonzero exit prevented writes. Figure, Word and PDF outputs need artifact inspection and rendered-page review before visual quality is claimed.
